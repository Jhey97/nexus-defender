QuarantineManager (Gerenciador de Quarentena)Esta é uma classe exposta para o Python (#[pyclass]) que funciona como uma lista negra de IPs mantida na memória RAM.HashSet<String>: Estrutura de dados que armazena elementos únicos sem uma ordem específica. Permite checar se um IP está na lista com tempo de resposta quase instantâneo ($O(1)$).Mutex (Exclusão Mútua): Como o Python suporta múltiplas threads simultâneas, o Mutex garante que apenas uma thread possa ler ou alterar a lista de IPs por vez, evitando corrupção de dados na memória.Métodos da Classe (#[pymethods]):new(): Construtor (__init__). Inicializa o conjunto de IPs vazio.isolate_ip(ip): Adiciona o IP à quarentena. Retorna true se o IP foi adicionado ou false se ele já estava lá.release_ip(ip): Remove o IP da quarentena.is_quarantined(ip): Verifica rapidamente se um IP está na quarentena.get_isolated_ips(): Clona todos os IPs guardados e os devolve como uma lista (Vec<String> em Rust, list em Python).2. calculate_entropy (Cálculo de Entropia de Shannon)Esta é uma função livre (#[pyfunction]) que recebe um payload de bytes (&[u8]) e calcula o nível de aleatoriedade dos dados, variando de 0.0 a 8.0.Para que serve em segurança?Dados de texto comum ou protocolos padrão possuem entropia baixa/média.Payloads criptografados, compactados ou arquivos maliciosos ofuscados têm entropia alta (próxima de 8.0).Como funciona o algoritmo:Cria uma contagem das ocorrências de cada um dos 256 valores de byte possíveis (usize; 256).Itera pelo pacote incrementando as frequências.Aplica a fórmula matemática da Entropia de Shannon usando o logaritmo na base 2: $H(X) = -\sum P(x) \log_2 P(x)$.3. core_rust (O Módulo Python)O bloco anotado com #[pymodule] é a "porta de saída" que o Python enxerga quando o arquivo compilado é importado.Rust#[pymodule]
fn core_rust(_py: Python, m: &PyModule) -> PyResult<()> { ... }

1. Configuração de Limiares (Thresholds)PythonLIMIAR_ENTROPIA_ALTA = 7.0
LIMIAR_RPS_ALTO = 80
Define os critérios para classificar uma requisição como anômala:Entropia $\ge 7.0$: Indica que o pacote contém dados altamente aleatórios ou criptografados (pode ser exfiltração de dados, malware ou payload ofuscado).RPS $\ge 80$: Indica uma taxa de requisições por segundo muito alta (possível ataque de DDoS ou Brute Force).2. gerar_telemetria_simulada()Função auxiliar que imita o tráfego de rede real:Tráfego Normal (75% das vezes): Gera uma requisição HTTP padrão (GET /api/v1/...), com baixa entropia e taxa de requisições moderada ($5$ a $45$ RPS).Tráfego Suspeito (25% das vezes): Gera um array de bytes inteiramente aleatórios (0 a 255), simulando um payload binário/criptografado e elevando o RPS ($70$ a $150$).3. processar_fluxo_trafego(queue_out)É a função principal do serviço, executada de forma assíncrona (async/await):Geração de Dados: Obtém os dados da requisição simulada (ip, payload_bytes, rps).Integração com Rust: Chama core_rust.calculate_entropy(payload_bytes). A computação pesada de análise dos bytes é delegada para o módulo em Rust compilado nativamente, garantindo latência mínima.Detecção de Anomalia: Se a entropia OU o RPS superarem os limiares definidos:Cria um objeto EventoAnomaliaBruta contendo ID único (uuid4), IP de origem, timestamp, métricas e amostra do payload.Exibe uma mensagem de alerta no terminal.Coloca o evento na fila assíncrona (await queue_out.put(evento)), repassando a informação para o próximo microserviço do sistema (que cuidará da mitigação/isolamento do IP).Pausa: Dorme por $0.5$ segundos (asyncio.sleep) antes de simular o próximo pacote, evitando sobrecarregar o terminal.Destaques de ArquiteturaUso de C/Rust Binds: Delegar a medição de entropia ao Rust evita o travamento da Event Loop do asyncio no Python, permitindo que a aplicação processe pacotes em altíssima velocidade.Comunicação Assíncrona via Fila: O uso de asyncio.Queue desacopla a Detecção do Processamento/Resposta, padrão fundamental em microserviços e arquiteturas reativas.






Este script implementa o Microserviço 3 (Motor de Defesa Autônoma) da arquitetura. Ele combina Aprendizado por Reforço (Q-Learning) com a extensão em Rust (core_rust) para tomar e executar decisões defensivas em tempo real.Visão Geral da Arquitetura[Diagnóstico de Ameaça (Fila)] ──► [Agente Q-Learning] ──► [Tomada de Decisão] ──► [Isolamento no Core Rust]
Componentes Principais1. QLearningDefenseAgent (O Cérebro)Classe que gerencia o modelo de Aprendizado por Reforço responsável por escolher qual contramedida aplicar a um IP suspeito.Matriz Q (self.q_table): Possui dimensões (5, 2, 5):5 Níveis de Ameaça: Derivados do enum NivelAmeaca (Valores de 1 a 5).2 Tipos de Ativo: Flag booleana (0 = Normal, 1 = Crítico).5 Ações Defensivas: Mapeadas em AcaoDefensiva (PERMITIR, MONITORAR, TARPIT, QUARENTENA_SANDBOX, BLOQUEAR_DROP)._inicializar_politica_base(): Preenche a tabela Q inicial com uma heurística base (warm start). Isso previne que o agente comece escolhendo ações completamente aleatórias ou destrutivas (ex: bloquear tráfego legítimo de nível 1).Política $\epsilon$-Greedy (escolher_acao):Com probabilidade $\epsilon$ (epsilon = 0.1), escolhe uma ação aleatória para explorar novas respostas.Com probabilidade $1 - \epsilon$ (0.9), escolhe a ação com maior valor Q (melhor decisão conhecida para aquele par estado-ação).2. AutonomousDefenseEngine (O Executor)Atua como o orquestrador que liga a inteligência do agente Python à execução física no estado do sistema.Instanciação: Conecta o agente de IA (QLearningDefenseAgent) ao gerenciador nativo de quarentena mantido na memória pelo Rust (core_rust.QuarantineManager).processar_defesa(queue_in) (Loop Principal):Consome assincronamente os eventos de diagnóstico vindos do microserviço anterior (queue_in.get()).Submete o nível de risco do diagnóstico ao agente de Q-Learning para obter uma recomendação de ação.Execução das Ações:Para TARPIT, QUARENTENA_SANDBOX ou BLOQUEAR_DROP, chama o método isolate_ip() da instância do Rust, registrando o IP no HashSet sincronizado via Mutex.Para PERMITIR ou MONITORAR, mantém o tráfego liberado.Exibe logs em tempo real detalhando a ação tomada e consulta o estado atual da quarentena usando get_isolated_ips().Notifica a fila que a tarefa foi concluída com queue_in.task_done().Por que esta abordagem é eficiente?Decisão Adaptativa: O uso de Q-Learning possibilita ajustar dinamicamente as respostas defensivas ao longo do tempo (via atualização de recompensas no ciclo de vida do modelo).Execução com Latência Quase Nula: Toda a lógica de verificação e bloqueio de IPs fica sob responsabilidade do QuarantineManager compilado em Rust, reduzindo o tempo de resposta do firewall/tarpit.Resiliência a Concorrência: As chamadas para isolamento de IPs no módulo Rust são seguras para execução concorrente no ambiente assíncrono do Python.




Este script implementa a Classe AttackGraphAnalytics, focada na análise avançada da topologia de rede e na propagação de risco através de Grafos de Ataque (Attack Graphs). Ele utiliza algoritmos de grafos e Álgebra Linear / Cadeias de Markov para modelar o movimento lateral de invasores pela infraestrutura.Estrutura e Conceitos PrincipaisO modelo utiliza três entradas fundamentais no construtor (__init__):adj_matrix ($A$): Matriz de adjacência $N \times N$, onde $A[i][j] > 0$ indica que o nó $i$ possui conectividade/acesso ao nó $j$.base_risks: Vetor com o valor numérico do risco inerente de cada servidor/nó (ex: vulnerabilidades CVSS presentes no nó isolado).alpha ($\alpha$): Fator de amortecimento ou desconto ($0.85$), usado para controlar a intensidade da propagação do risco entre conexões vizinhas.Bloco A: Análise Recursiva de Risco Acumulado (DFS com Memoização)O método calcular_risco_acumulado_dfs calcula quanto risco um determinado nó concentra, considerando não apenas a sua própria vulnerabilidade, mas também o risco acumulado de todos os nós que ele pode alcançar:$$\text{Risco}(u) = \text{RiscoBase}(u) + \alpha \sum_{v \in \text{Vizinhos}(u)} \text{Risco}(v)$$Características Técnicas:Busca em Profundidade (DFS): Explora as rotas de ataque nó a nó até a profundidade limite (max_depth).Proteção contra Ciclos (visited): Evita loops infinitos em redes com rotas bidirecionais utilizando um conjunto de rastreamento de nós visitados.Memoização (memo): Aplica Programação Dinâmica armazenando os resultados do par (nodo, profundidade). Isso reduz dramaticamente a complexidade computacional para $O(V + E)$ (onde $V$ é o número de vértices/nós e $E$ é o número de arestas/conexões), impedindo reprocessamento desnecessário do mesmo caminho.Bloco B: PageRank de Ameaças & Cadeias de Markov via Power IterationEm vez de medir apenas o acesso direto, este módulo calcula a centralidade de relevância de ataque da rede usando uma variação do algoritmo Google PageRank adaptado para cibersegurança (Markov Threat PageRank).1. construir_matriz_estocastica()Transforma a matriz de adjacência pura em uma Matriz de Transição de Probabilidade ($P_{\text{markov}}$):Normalização por Grau de Saída: Divide os pesos da matriz pelo total de conexões de saída do nó, garantindo que a soma de cada linha seja $1$ (Propriedade Estocástica).Matriz de Teleporte ($E$): Adiciona o fator de amortecimento $\alpha$ para simular o comportamento de um atacante que pode transitar pelas conexões existentes ($\alpha$) ou realizar um salto "aleatório" / exploit direto para qualquer outro ponto da rede ($1 - \alpha$).$$\mathbf{P}_{\text{markov}} = \alpha \mathbf{P} + (1 - \alpha) \mathbf{E}$$2. calcular_pagerank_ameaca()Encontra o autovetor estacionário da cadeia de Markov usando o método numérico Power Iteration (Iteração de Potência):O Princípio: Executa sucessivas multiplicações vetor-matriz $v^{(t+1)} = v^{(t)} \cdot P$ até que o vetor de distribuição de probabilidades convirja (diferença $L_1 < \text{tol}$).O Resultado (v): Retorna o vetor de centralidade dominante ($\lambda_1 = 1$).Aplicação Prática no SistemaIdentificação de "Nós Pivô" (Crown Jewels & Bastions): Servidores com pontuação alta no Threat PageRank são os alvos mais valiosos ou os pontos de pivoteamento mais perigosos para movimento lateral no ambiente.Priorização do Motor de Defesa: O resultado destas análises pode alimentar os agentes de Q-Learning do sistema, permitindo definir dinamicamente se um nó afetado é ativo_critico=True, aplicando contramedidas mais severas no core compilado em Rust.
